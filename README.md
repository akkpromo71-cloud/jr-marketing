# J/R marketing

Платформа, соединяющая артистов и видеоэдиторов (TikTok/Reels).
Next.js (App Router) + Supabase (Auth, Postgres, RLS). Дизайн-система «Label Noir»
перенесена из интерактивного мокапа.

**MVP-объём (по договорённости): только основной цикл, без реальных платежей.**
Заявки, модерация эдиторов, публикация треков, отклики, правки — работают.
Выплаты и эскроу пока не подключены (см. «Что дальше» ниже).

## Важно про эту сборку

Проект написан вручную, файл за файлом, без запуска `npm install` в этой среде —
у песочницы, в которой я работаю, нет доступа к npm-реестру (сетевые ограничения
организации). Поэтому зависимости не установлены и `next build` здесь не запускался.
Код написан аккуратно и по стандартным паттернам Next.js 15 / Supabase SSR, но
**первым делом после распаковки стоит прогнать `npm run build` у себя**, чтобы
поймать опечатки, если они где-то остались.

## Стек

- **Next.js 15** (App Router, Server Actions, Server Components)
- **Supabase**: Postgres + Auth + Row Level Security
- **Tailwind CSS 3** — токены цвета/тени вынесены в CSS-переменные (`src/app/globals.css`),
  светлая и тёмная тема как в мокапе
- Шрифты: Fraunces (заголовки) + Manrope (текст), через `next/font/google`

## Быстрый старт

1. Установите зависимости:

   ```bash
   npm install
   ```

2. Создайте проект на [supabase.com](https://supabase.com) (бесплатного тарифа хватит для старта).

3. В Supabase Dashboard → SQL Editor выполните целиком файл `supabase/schema.sql`.
   Он создаст таблицы `profiles`, `campaigns`, `applications`, `revision_messages`,
   включит Row Level Security и политики доступа.

4. Скопируйте `.env.example` в `.env.local` и вставьте данные из
   Supabase Dashboard → Project Settings → API:

   ```bash
   cp .env.example .env.local
   ```

5. Запустите локально:

   ```bash
   npm run dev
   ```

   Откройте http://localhost:3000

6. Зарегистрируйте первого пользователя как артиста или эдитора через сайт,
   затем в Supabase Dashboard → Table Editor → `profiles` вручную поставьте
   этому пользователю `role = admin`, чтобы получить доступ к `/admin`.

## Структура проекта

```
src/app/
  page.tsx                    landing / выбор роли
  (auth)/login, signup/...    вход и регистрация (артист/эдитор)
  feed/                       лента открытых треков (для эдиторов)
  applications/               "Мои заявки" + чат по правкам (applications/[id])
  dashboard/                  кабинет артиста: кампании, создание, отклики
  admin/                      модерация эдиторов, согласование цены, обзор кампаний
src/lib/supabase/             клиенты Supabase (browser / server / middleware)
src/components/                переиспользуемые UI-компоненты (Label Noir)
supabase/schema.sql           вся схема БД + RLS одним файлом
```

## Основной цикл (как это работает)

1. **Эдитор регистрируется** → указывает желаемую цену, соцсети, портфолио →
   попадает в `profiles.editor_status = 'pending'`.
2. **Админ** в `/admin` видит заявку, согласовывает финальный диапазон цены
   и лимит одновременных заказов, нажимает «Одобрить» → `editor_status = 'approved'`.
3. **Артист** публикует трек (`/dashboard/new`) → кампания появляется в общей ленте.
4. **Эдитор** в `/feed` откликается на трек со своей ценой и сообщением.
5. **Артист** в `/dashboard/campaigns/[id]` видит отклики, принимает или отклоняет заявку.
6. После принятия — **чат по правкам** (`/applications/[id]`): обе стороны переписываются,
   эдитор сдаёт готовую ссылку на видео, артист принимает работу или отправляет на правки.

Права на изменение статуса заявки защищены не только RLS-политиками, но и
Postgres-триггером (`check_application_transition` в `schema.sql`) — эдитор не может
сам себе поставить «принято», а артист не может поставить «сдано» вместо эдитора.

## Деплой

Самый простой вариант — [Vercel](https://vercel.com): подключить репозиторий,
указать те же переменные окружения из `.env.local` в настройках проекта, и Vercel
сам установит зависимости и соберёт проект (в отличие от этой песочницы, у Vercel
есть доступ к npm-реестру).
